    ## Detailed summary

## Overview
Martin y Nahuel conversaron el 22 de septiembre de 2026 sobre las funcionalidades, problemas y prioridades de un sistema de gestión de producción textil que actualmente combina una aplicación inestable y múltiples planillas Excel; acordaron definir un alcance mínimo entregable para febrero y recopilar accesos/Excel de ejemplo para avanzar en el análisis.

## Resumen detallado

- Objetivo principal tratado
  - Diseñar/mejorar un sistema que permita medir y controlar el uso de telas por rollo y estimar consumo por prenda (remeras, pantalones, shorts, etc.), integrando tizadas, stock de rollos, cortes, programación, control de producción, control de calidad y envíos.

- Módulos y funcionalidades descritas como necesarias
  - Gestión de tizadas (patrones/piezas)
    - Debe permitir seleccionar pisadas, cantidad de copias y asociarse al tipo de prenda.
    - Las tizadas se usan para calcular cuántas prendas salen por corte.
  - Gestión de rollos / stock de telas
    - Carga de rollos con peso (kg), largo aproximado (m) y ancho (obligatorio).
    - Al asociar rollos a un corte, el sistema debe descontar stock real y permitir editar cantidades reales (ej. sistema sugiere 15 capas, pero se hicieron 14).
    - Historial de rollos usados y stock real.
  - Configuración de tipos de tela y prendas
    - Registrar telas, unidades de medida (metro/kilo), anchos, colores y variantes.
    - Registrar prendas compuestas por varias telas (principal + secundarias) y fichas de composición (especificaciones técnicas, estampados, piezas).
  - Módulo de cortes y programación
    - Crear cortes con responsable, tipo de prenda, tipo de tela, bloques de confección (capas), cronograma y asignación de rollos disponibles.
    - Posibilidad de editar bloques y multiplicidad.
  - Control de producción y control de calidad
    - Registrar entregas parciales y finales desde talleres y estampadores.
    - Registrar prendas buenas y fallas unitarias con detalle (ej.: talle, tipo de falla) y permitir marcar arreglada / no arreglada / enviada al taller.
    - Soporte para "guardado parcial" que bloquee valores entregados (editable solo por administradores).
    - Registro de mermas (prendas y telas no recuperables).
  - Gestión de insumos y componentes (avíos)
    - Control de elementos comprados a proveedores: elásticos, cierres, etiquetas, botones, etc., con stock mínimo y movimientos por producción.
    - Cálculo estimativo automático de consumo de insumos por orden (ej.: metros de elástico por talle/cantidad).
  - Historiales, métricas y estadísticas
    - Generar reportes de metros de tela usados, cortes realizados, costos históricos por producto (ej.: precio de producción en mayo vs ahora), y métricas requeridas para tesis/probabilidades.
  - Envíos / logística (viajes de cadetería)
    - Registro de viajes con fecha, taller origen/destino, acción (retirar/llevar), responsable, dirección, teléfono, horario, observaciones y tipo de jornada (completo/media) para viáticos.
  - Roles y permisos de usuario
    - Diferentes niveles de acceso (ej.: responsables de corte, administradores, visualizadores) para controlar quién puede editar qué.
  - Integraciones
    - Conexión (o al menos compatibilidad) con el sistema de facturación/tienda (actualmente Tienda Nube) para control de stock de venta, y enlace con el módulo de estampado y talleres externos.
  - Interfaz y usabilidad
    - Registro histórico y visualización clara por taller (colores para identificar envíos), posibilidad de cargar remitos y comparar lo enviado vs. lo recibido.

- Problemas actuales y limitaciones del sistema vigente
  - El módulo de stock en la aplicación anterior fue eliminado por hacerlo lento/pesado.
  - Las planillas Excel son múltiples y fragmentadas: control de cortes, control de producción, stock de rollos, maestro de envíos, hoja por taller; gran parte del flujo se realiza manualmente.
  - Falta de automatización en el cálculo de insumos (actualmente formulas en Excel que se pierden al migrar).
  - El sistema actual no maneja bien entregas parciales ni estados intermedios (necesidad de guardado parcial).
  - Falta de trazabilidad en algunos procesos: estampado como proceso separado (entregas parciales) y registro de envíos.
  - El sistema tiene partes desarrolladas pero fragmentadas y sin acceso directo al código; se ofreció acceso con usuario de solo lectura para revisar funcionamiento.

- Requisitos operativos y datos adicionales mencionados
  - Necesidad de mantener un "Excel maestro" que Nahuel usa para conciliar lo que se envía a taller vs lo que el taller remite (incluye taller, tipo de tela, número de corte, fecha).
  - Registro de talleres por hoja y codificación por color para rastreo (ej.: Percy, Mario, Janeth, Jacinto, 14 de septiembre).
  - Control de calidad en tres puntos: llegada del taller, salida a estampado y regreso del estampado.
  - Registro de viajes y cadetería a cargo de Santiago con hoja que indica días de media jornada (color verde).
